# Publishing guide

This repo is ready to publish to **GitHub** and the **VS Code Marketplace**.
A few placeholders must be filled in first.

---

## 1. Fill in the placeholders

Search the repo for `REPLACE_WITH_` and replace every occurrence:

| Placeholder | Where | Put |
|---|---|---|
| `REPLACE_WITH_YOUR_PUBLISHER_ID` | `package.json` → `publisher` | Your Marketplace **publisher ID** (created in step 3) |
| `REPLACE_WITH_YOUR_NAME` | `package.json` → `author.name`, and `LICENSE` (`<YOUR NAME>`) | Your name |
| `REPLACE_WITH_YOUR_GITHUB_USERNAME` | `package.json` → `repository`, `bugs`, `homepage` | Your GitHub username |

Quick check after editing:

```bash
grep -rn "REPLACE_WITH" .        # should print nothing
grep -n "<YOUR NAME>" LICENSE     # should print nothing
```

---

## 2. Push to GitHub

```bash
cd c-call-depth
git init
git add .
git commit -m "Initial public release: C Stack Analysis & Call Graph"
git branch -M main
# create an empty repo named c-call-depth on GitHub first, then:
git remote add origin https://github.com/<your-username>/c-call-depth.git
git push -u origin main
```

`out/`, `node_modules/`, and `*.vsix` are intentionally git-ignored — the build
output is regenerated by `npm run compile`.

---

## 3. Create a Marketplace publisher (one time)

1. Sign in at <https://marketplace.visualstudio.com/manage> with a Microsoft
   account.
2. Create a **publisher** — its ID is what goes in `package.json` → `publisher`.
3. Create a **Personal Access Token (PAT)**:
   - Go to <https://dev.azure.com> → User settings → Personal access tokens.
   - Scope: **Marketplace → Manage**. Organization: **All accessible**.
   - Copy the token (you only see it once).

---

## 4. Build and publish

```bash
npm install                 # dev dependencies (typescript, @types, vsce, jsdom)
npm run compile             # src -> out
npx @vscode/vsce login <your-publisher-id>   # paste the PAT when prompted
npx @vscode/vsce publish                      # reads version from package.json
```

To bump the version automatically while publishing:

```bash
npx @vscode/vsce publish patch   # or: minor | major
```

### Or just produce the .vsix without publishing

```bash
npx @vscode/vsce package         # -> c-call-depth-<version>.vsix
```

Users can then install it via **Extensions → … → Install from VSIX**.

---

## 5. Runtime requirements (mention in your Marketplace description)

This extension shells out to a bundled Python CLI that parses the project with
**libclang**. End users need:

- **Python 3** on `PATH`
- `pip install libclang`
- A `compile_commands.json` for the C project (e.g. via CMake or Bear)
- GCC `-fstack-usage` `.su` files for stack-frame sizes (optional but recommended)

See the README for the full setup.

---

## Notes

- **Source ↔ build are in sync.** Editing `src/*.ts` and running `npm run compile`
  reproduces the shipped behavior. Do not hand-edit `out/*.js`.
- `.vscodeignore` keeps the packaged `.vsix` small (no `node_modules`, `test/`,
  `workspace/`, `src/`, or source maps).
- The extension is **not** tool-qualified for DO-178C; it is an engineering aid.
